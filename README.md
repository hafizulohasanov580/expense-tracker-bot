# Трекер расходов в Telegram

Бот в Telegram + веб-панель для учёта личных трат. Написал сумму боту —
трата сохранилась; открыл панель — увидел, куда уходят деньги.

- **Бот:** [t.me/Rashod_tj_bot](https://t.me/Rashod_tj_bot)
- **Веб-панель:** https://stkevjznrrbcfvkxrxut.supabase.co/functions/v1/app (открывается по кнопке из бота, без пароля)

## Как это работает

- «кофе 350» — сохранит трату 350 ₽ с описанием «кофе», категория определится
  автоматически по ключевым словам.
- «такси 900 транспорт» — то же самое, но категория указана явно последним словом.
- `/today`, `/week`, `/month` — итоги за период текстом прямо в чат.
- `/panel` (или кнопка после `/start`) — одноразовая ссылка на веб-панель,
  открывает её без пароля и без регистрации (авторизация происходит через сам факт,
  что ссылку мог получить только владелец Telegram-аккаунта).
- `/last` — последние 5 трат с кнопкой «Удалить».
- `/edit ID сумма описание категория` и `/del ID` — исправить/удалить трату из бота.
- `/limit категория сумма` — месячный лимит по категории; при его превышении бот
  сам пришлёт предупреждение после следующей траты в этой категории.
- В панели: итоги и разбивка по категориям (сегодня/неделя/месяц), список трат по
  дням, редактирование и удаление трат, лимиты по категориям, экспорт в CSV.
  Адаптирована под телефон.

## Архитектура

Всё — на Supabase (Postgres + Edge Functions), без отдельного сервера:

```
Telegram  ──webhook──▶  Edge Function "app"  ──▶  Postgres (RLS, доступ
   ▲                     ├─ /bot   (апдейты бота)      только через service role)
   │                     ├─ /      (HTML веб-панели)
   └──── inline-кнопки   └─ /api/* (JSON API панели)
```

Один edge-function-процесс обслуживает и бота (webhook), и панель, и её API —
меньше движущихся частей, один деплой. Данные каждого пользователя изолированы
по `telegram_id`: в каждом запросе к БД есть фильтр `user_id = <ваш telegram_id>`,
а сами таблицы закрыты RLS от прямого публичного доступа — прочитать чужие
траты через автогенерируемый REST API Supabase невозможно.

Вход в панель — по одноразовой ссылке с токеном, которую присылает бот
(`/panel` или кнопка при `/start`). Токен обменивается на сессионную HttpOnly-
cookie, дальше панель работает как обычное веб-приложение.

### Структура репозитория

```
supabase/
  migrations/            SQL-схема БД (users, expenses, budgets, sessions, ...)
  functions/app/
    index.ts             HTTP-роутер: бот-вебхук + API + отдача панели
    render.ts             HTML/CSS/JS веб-панели (без сборки, без CDN)
    categorize.ts          парсинг сообщений и автокатегоризация
    db.ts                  клиент к Postgres (PostgREST) на service role key
    telegram.ts             обёртка над Telegram Bot API
    util.ts                  даты/куки/CSV
scripts/set-webhook.sh   один раз прописать вебхук боту
.env.example
```

## Запуск локально

Нужен [Supabase CLI](https://supabase.com/docs/guides/cli) и Deno (входит в CLI).

```bash
supabase login
supabase link --project-ref <ваш-project-ref>
supabase db push                      # применить миграции из supabase/migrations
cp .env.example .env                  # заполнить переменные ниже
supabase functions serve app --env-file .env --no-verify-jwt
```

Функция поднимется на `http://localhost:54321/functions/v1/app`. Чтобы Telegram
мог достучаться до неё вебхуком, пробросьте порт наружу (например, `ngrok http 54321`)
и укажите публичный URL в `PANEL_URL` при вызове `scripts/set-webhook.sh`.

### Переменные окружения

| Переменная | Обязательна | Где взять |
|---|---|---|
| `SUPABASE_URL` | да (локально) | Supabase Dashboard → Settings → API. В проде подставляется автоматически. |
| `SUPABASE_SERVICE_ROLE_KEY` | да (локально) | Там же. В проде подставляется автоматически, наружу никогда не уходит. |
| `TELEGRAM_BOT_TOKEN` | да | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `TELEGRAM_WEBHOOK_SECRET` | да | любая случайная строка, проверяет, что вебхук дёргает именно Telegram |

В продакшене `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` можно не задавать
как секреты функции, а один раз положить в таблицу `settings` — так и сделано
в задеплоенной версии (см. `db.ts`, `getSetting`): сначала проверяется
переменная окружения, если её нет — берётся значение из БД.

После того как бот и функция подняты — один раз пропишите вебхук:

```bash
TELEGRAM_BOT_TOKEN=... TELEGRAM_WEBHOOK_SECRET=... PANEL_URL=https://<ref>.supabase.co/functions/v1/app \
  ./scripts/set-webhook.sh
```

## Бонусы, которые реализованы

- Несколько валют: бот распознаёт `$`/`usd` и `€`/`eur` в сумме, панель показывает
  итоги отдельно по каждой валюте (без конвертации по курсу).
- Лимиты по категориям с предупреждением в боте (`/limit`, а также кнопка
  «🎯 Лимиты» в панели).
- Экспорт в CSV — кнопка «⬇️ Экспорт CSV» в панели.

Не реализовано (сознательно, чтобы не жертвовать качеством обязательной части):
распознавание сумм по фото чека (нужен внешний OCR-сервис и его ключ) и общие
бюджеты на двоих.

## Разработка

`dev/` — вспомогательные скрипты для ручного QA (не часть деплоя):
`test_parse.js` проверяет парсинг сообщений и автокатегоризацию,
`smoke_test.js`/`smoke_test2.js` открывают отрендеренную панель в headless-браузере
(Playwright) и проверяют, что интерфейс собирается без ошибок.

## Известные ограничения

- Бесплатный проект Supabase «засыпает» примерно через неделю простоя — первый
  запрос после паузы может занять несколько секунд, пока база поднимается снова.
- Дни/недели/месяцы считаются по московскому времени (UTC+3), это захардкожено
  в `util.ts` (`TZ_OFFSET_MINUTES`) — при необходимости легко вынести в настройку
  пользователя.
